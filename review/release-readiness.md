## Merge hazards in PR #27, recorded before any consolidation

1. **The file names differ, so a naive merge creates duplicate definitions.**
   PR #27 adds `R/mm_collinearity.R`, `R/mm_decision_curve.R` and
   `R/mm_recalibrate.R`; this tree has `R/collinearity.R`,
   `R/decision_curve.R` and `R/recalibrate.R`. Merging both leaves
   `mm_recal_slope()`, `mm_decision_curve()` and nine others defined in two
   files, which is the specification's section 3.3 hard stop.
2. **PR #27 does not export `mm_calculator()`.** It branched from a `main`
   with 10 exports, predating the calculator. Taking its `NAMESPACE` as text
   would drop the patient-facing calculator, which is the subject of the D-1
   decision. `NAMESPACE` must be regenerated by `document()` on the
   consolidated tree, never merged as text.
3. **PR #27's `Suggests` omits `caret`, `shiny` and `dcurves`**, which this
   tree needs for the estimability, calculator and decision-curve tests. Same
   cause: its branch point predates them. `DESCRIPTION` must be reconciled by
   hand, not taken from either side.
4. **`review/import-candidates-from-nomogram-final.md` exists in both lines
   with different content** (248 lines here, 103 there). A merge will conflict
   on this path and must resolve toward this tree's version.

## Scope note on the detection rate

The 12 of 12 result is detection over the twelve defects injected into the
three newly ported modules. It is **not** a coverage figure for the package,
and the 34-row ledger is not a package-wide detection rate either: those rows
are three separate campaigns against different subjects. Two rows are
classified SURVIVED, both subsequently covered by `test-mutation-gaps.R`.

## Recommendation

**Do not merge to a protected branch.** Independent review is the blocking
gate and is unchanged in status. The three ported modules are, in this tree,
documented, tested and mutation-verified, and `R CMD check` is clean on them;
that is a defensible candidate baseline for consolidation, and it is not a
release.
